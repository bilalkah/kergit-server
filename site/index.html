C++ / real-time systems / voice

A communication platform built below the UI.

Kergit is a Discord-like text and voice project with a C++ signaling core, protobuf over WebSocket, and LiveKit as its media plane. The interesting work is in the boundary between them: sessions, state, backpressure, reconnects, and voice ownership.

The premise

Media can be delegated.
Authority cannot.

LiveKit moves audio and video. Kergit's backend still decides who may join, which session owns voice, which node to use, what a token may do, and how reconnects and webhook events change application state.

Engineering decisions

The difficult paths are explicit.

01 / transport

Protobuf inside a stable envelope

Commands, snapshots, deltas, and transient signals share one versioned outer protocol without sharing recovery semantics.

02 / load

Backpressure is policy

Priority queues and per-connection outboxes isolate slow consumers. Repairable signals may be dropped; authoritative mutations may not.

03 / voice

Ownership belongs to a session

A user may have several tabs, but one session owns voice. Resume and takeover paths can revoke the previous owner deliberately.

04 / recovery

Reconciliation before cleanup

A WebSocket drop does not immediately remove a healthy media connection. Confirmed evidence and grace periods drive convergence.

Protocol surface

A small outer shape for an evolving system.

Transport stays predictable while application messages evolve. Durable deltas can be repaired through state sync; typing and presence signals are intentionally treated as transient.

Current boundary

Advanced prototype, documented honestly.

Kergit demonstrates the architecture and core flows. It is not presented as a production-ready service.

Implemented

  • Authenticated sessions and initial state sync
  • Hub, channel, text chat, and invite flows
  • Priority queues and per-connection output buffering
  • Voice join, revoke, takeover, and resume paths
  • Health, metrics, and operator control surfaces

Still being hardened

  • Voice and video user experience
  • Dynamic multi-node LiveKit validation
  • Production deployment and operational cleanup
  • Consistent C++ standard settings across all build targets
