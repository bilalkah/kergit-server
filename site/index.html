One click, four boundaries

What “join voice” actually means.

Voice is not a direct browser-to-room shortcut. Kergit makes authorization and ownership explicit before media starts.

  1. 01
    VOICE_JOIN →

    Request

    The active browser session asks to enter a specific voice channel.

  2. 02
    AUTHZ ✓

    Authorize

    The C++ core validates membership and assigns voice ownership to one session.

  3. 03
    TOKEN ←

    Issue

    A narrow LiveKit token names the room, participant, permissions, and selected node.

  4. 04
    RECONCILE ↻

    Converge

    Webhooks, reconnect grace, and resume paths bring media and application state back together.

Engineering decisions

Hard paths made visible.

Kergit is a systems project disguised as a community app. These are the choices that make the prototype interesting beyond its interface.

01 load control

Backpressure is product behavior.

Per-connection outboxes and priority classes isolate slow consumers. Repairable signals can be dropped; authoritative mutations cannot.

P0state mutation
P1message delta
P2presence
P3typing · droppable
02 protocol surface

One envelope, different recovery semantics.

message Envelope {
  uint32 version = 1;
  Type   type    = 3;
  bytes  payload = 100;
}

03 voice ownership

A user can have many tabs. Voice has one owner.

user / bilal

Takeover and resume revoke the previous owner deliberately instead of letting tabs race.

04 recovery

Disconnect is evidence, not truth.

A dropped WebSocket does not instantly erase a healthy media participant.
